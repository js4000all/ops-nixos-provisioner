# 実機固有設定のローカルGit運用

## 現在の方式

`install.sh` はNixOS Minimal ISO上でディスク・起動モード・有線NICを検出し、`hardware-configuration.nix`、`network-local.nix`、`boot-local.nix` を生成します。これらは公開リポジトリの `main` では `.gitignore` の対象です。

生成後にインストーラーは `c0-local` ブランチを作成し、3ファイルだけを `git add -f` でステージしてローカルコミットします。これによってGit flakeは生成ファイルを評価でき、`path:` 指定はディスク構築前の一時評価だけに限定されます。

ローカルブランチは `origin/main` を追跡し、`git pull --rebase` で上流の更新を取り込みます。ローカルのpushはGit設定で抑止します。ただし、この設定は強制的なセキュリティ境界ではありません。リモートに送らないことが運用上の前提です。

## 未解決の課題

1. **ディスク識別の安定性**：`boot-local.nix` の `myHost.bootDisk` はインストール時に検出した `/dev/sdX` 等の名前です。デバイス列挙順が変わると将来のGRUB更新時に不適切になる可能性があります。`/dev/disk/by-id` 等の安定した識別子の導入、およびdiskoとGRUBでの利用方法を検討します。
2. **起動方式の変更**：`myHost.bootMode` はインストールISOが実際に起動したモードを記録します。インストール後にUEFI/Legacy BIOSを変更する場合、ローカル設定とブートローダーを合わせて移行する必要があります。
3. **NIC名の変動**：`myHost.primaryEthernet` に記録するインターフェース名は、命名規則やハードウェア構成の変化に左右されます。物理有線NICへの名前非依存のマッチングとWoL設定を検討します。
4. **ハードウェア設定の可搬性**：`hardware-configuration.nix` は実機で生成します。共通の汎用モジュール構成へ移せるか、initrdの必要ドライバも含めて検証します。
5. **再現可能性と履歴**：GitHubの `main` のSHAだけでは、ローカルコミットを含む完全な評価入力を再現できません。OS世代と「上流コミット・ローカルコミット」の対応付け、ローカル設定のバックアップ方針を検討します。rebaseによりローカルコミットのSHAは変わります。
6. **更新時の競合**：上流が実機専用ファイルと同じパスを新たに管理した場合、rebaseが競合します。Git管理外の秘密情報をこの仕組みに入れないこと、ローカルの未コミット変更を確認すること、競合時に自動続行しないことを運用条件とします。
7. **既存インストールの移行**：既に `path:/etc/nixos` 方式で構築済みのPCには、インストーラー変更は遡及しません。3ファイルのローカルコミットと専用ブランチの作成を手動で行う移行手順を別途検証します。

## 検証項目

- 新規インストール後、`git status -sb` が `c0-local` を示し、作業コピーがクリーンである。
- `git ls-files` に3ファイルが含まれ、`git log` にローカル専用コミットが存在する。
- `nixos-rebuild dry-build --flake .#c0` と `switch` が成功する。
- 上流main更新後に `git pull --rebase` が成功し、ローカルコミットが先端に残る。
- 間違って `git push` してもローカル設定が公開されない。
- BIOS/UEFI、mDNS、SSH、WoL、蓋閉じ抑止が従来どおり機能する。
